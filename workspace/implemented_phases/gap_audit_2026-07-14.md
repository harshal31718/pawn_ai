## F-9 `[fixed]` Full pytest gate's real root cause: SQLite checkpointer contention on the Windows bind mount, not a langchain-core sandbox artifact
User ran `docker compose build backend && docker compose exec backend pytest
-n auto` for real. Result: 16 failed, ALL `sqlite3.OperationalError: unable

just be "expected green in Docker." Root cause: every `/chat`-touching test

for Windows bind mounts are a known bad combination for file locking. Fixed:
`tests/conftest.py` now sets `PAWN_DATA_DIR` to a throwaway directory unique
per xdist worker (`PYTEST_XDIST_WORKER`), before any `app.*` module import —
same established pattern as the file's existing `JWT_SECRET`/
`ENCRYPTION_SECRET` overrides. Verified safe: `registry.loader.load_registry`
self-heals via `seed_registry()`. Committed as `ea765df`. **Not yet
re-verified against real Docker** — needs the user to re-run the gate.
